# Новый раздел «Мои работы»

## Как это делают топовые студии

Я посмотрел, как оформляют портфолио агентства уровня Ramotion и Halo Lab. Общие приёмы:

- Один-два **акцентных кейса крупно** сверху, остальные — компактнее. Не «шесть одинаковых плиток».
- Скриншот **в рамке-мокапе** (окно браузера / ноутбук) — так разные сайты выглядят как одна коллекция, а не как случайные картинки.
- Под превью — **результат словами**, а не просто название («заявки идут с сайта, а не с телефона»).
- Клик ведёт **на страницу кейса**, а не в попап. Так делают все — потому что страница индексируется Google и её можно скинуть ссылкой клиенту.

Мой ответ на ваши два вопроса:
- **Клик → страница кейса.** Страницы `/uk/cases/...` у нас уже готовы и заполнены (задача / решение / результат). Сейчас они фактически спрятаны — из портфолио на них никто не попадает. Попап оставим как вторичное действие (кнопка «Швидкий перегляд») для тех, кто хочет просто глянуть скриншот.
- **Скриншоты — в рамке браузера.** Единый мокап с адресной строкой и настоящим доменом сайта. Это самый надёжный вариант: выравнивает разнокалиберные скриншоты и добавляет доверия (видно реальный домен клиента).

## Что делаем

```text
┌──────────────────────────────────────────────┐
│  Мої роботи                                  │
│                                              │
│  ┌────────────────────┐  Категорія           │
│  │  [рамка браузера]  │  Название кейса      │
│  │   большой скрин    │  Результат 2 строки  │
│  │                    │  теги · країна · рік │
│  └────────────────────┘  [Дивитись кейс] [↗] │
│                                              │
│  ← ─── горизонтальная лента остальных ─── →  │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │
│  │ карт │ │ карт │ │ карт │ │ карт │  ○○●○   │
│  └──────┘ └──────┘ └──────┘ └──────┘         │
└──────────────────────────────────────────────┘
```

1. **Акцентный кейс сверху** — первый проект крупно, в две колонки: слева скриншот в рамке браузера, справа категория, заголовок, короткий результат, теги, страна и год, кнопки «Дивитись кейс» и «Відкрити сайт ↗».
2. **Карусель остальных** — горизонтальная лента карточек с прокруткой мышью/свайпом, стрелками и точками-индикаторами. Карточки одинаковой высоты, тот же мокап браузера, кликабельны целиком.
3. **Данные берём из `src/data/cases.ts`** — сейчас портфолио дублирует проекты вручную своим списком, из-за чего описания на главной и на страницах кейсов расходятся. Один источник = одинаковый текст на всех трёх языках.
4. **Клик** по акцентному кейсу и по карточке ведёт на страницу кейса нужного языка. Кнопка «↗» открывает живой сайт в новой вкладке. Попап остаётся на кнопке быстрого просмотра.
5. **Стиль** — существующий: тёмная тема, фиолетовый акцент, тонкие рамки, без градиентов и теней. Анимации сдержанные: лёгкий подъём карточки и мягкое приближение скриншота при наведении.

## Технические детали

- `PortfolioSection.tsx` переписывается: убираем локальный массив `portfolioItems`, читаем `CASES` из `src/data/cases.ts` + текущий язык из `i18n`.
- Новые компоненты в `src/components/portfolio/`: `BrowserFrame.tsx` (рамка с адресной строкой), `FeaturedCase.tsx`, `CaseCarousel.tsx` (scroll-snap на CSS + кнопки прокрутки, без внешних библиотек).
- Ссылки строятся через уже существующий `src/lib/i18n-routes.ts`, чтобы работали `/uk`, `/en`, `/pl`.
- Превью-картинки остаются те же (`*_hero.jpg`), новые файлы не генерируем.
- Тексты берутся из `content[lang]` кейсов; в i18n-файлах чистим ставшие ненужными ключи `portfolio.projectN.*`, заголовок секции и кнопку оставляем.
- Доступность: карусель — со стрелками, кнопками с aria-label и прокруткой с клавиатуры; каждая карточка — `<article>` со ссылкой.
