# Исправление 5 предупреждений на главном адресе

Все замечания относятся к одному адресу — `https://leonforge.com/` (без языка). Сейчас этот адрес сам по себе пустой: он только мгновенно перебрасывает посетителя на `/uk`. Человек этого не замечает, а поисковый робот видит страницу без заголовка, без текста и без ссылок — отсюда «Missing H1», «Thin content», «Page has no outgoing links», а также «Duplicate title» в паре с `/uk`.

## Что сделаем

1. **Главный адрес будет показывать настоящую украинскую главную страницу** — с заголовком, текстом, меню и ссылками, точно так же, как `/uk`. Для посетителя ничего не меняется: адрес в строке браузера по-прежнему сразу становится `/uk`.
2. **Укажем `/uk` как основной адрес** этой страницы (canonical + hreflang x-default), чтобы Google не считал `/` и `/uk` конкурирующими и не делил между ними вес. Это же снимает предупреждение о повторяющемся заголовке — Google объединит два адреса в один.
3. **Перепроверим готовые файлы страницы** после сборки: убедимся, что в `/` есть заголовок первого уровня, текст и ссылки, и что все указания ведут на `/uk`.
4. **Опубликуем сайт** — без публикации поисковики продолжат видеть старый пустой вариант.

## Технические детали

- `src/App.tsx`: маршрут `/` вместо `RootRedirect` рендерит `<Index lang={...} />` с определением языка, как сейчас, и заменяет адрес на языковой через `history.replaceState` / `<Navigate replace>` уже после первой отрисовки (чтобы предрендер Puppeteer успел получить полный HTML).
- Предрендер должен фиксировать контент для `/` — событие `render-event` в `src/main.tsx` не должно срабатывать до отрисовки контента.
- `src/hooks/useSEO.ts` / `LangLayout.tsx`: для пути `/` canonical = `https://leonforge.com/uk`, набор hreflang остаётся прежним.
- `/` в `prerender-routes.json` остаётся; в `sitemap.xml` его нет и добавлять не нужно.
- Проверка: `bun run build`, затем чтение `dist/index.html` (наличие `<h1>`, `<a href>`, canonical).
